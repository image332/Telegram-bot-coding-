# YouTube setup

YouTube often blocks anonymous downloads with a "Sign in to confirm you're not a bot" check. Many public videos still work without anything extra. For the others, the bot needs a `cookies.txt` file exported from a browser where you are signed in to YouTube.

## How the bot behaves

- **No cookies file:** YouTube requests are made publicly. The bot does not stop because the file is missing.
- **Cookies file present:** the bot makes a private, repaired copy for each YouTube request and deletes it afterwards. Your original file is never changed.
- **Cookies are used for YouTube only.** TikTok, Instagram, X, Reddit and the other sites never receive them.
- Cookie values are never printed, logged or sent to Telegram.

## 1. Use a secondary account

Cookies are a login session. Anyone who has your cookies file can act as you on YouTube. Use a secondary Google account that you do not mind risking, not your main account. Keep the file private.

## 2. Export cookies.txt from your browser

1. Sign in to YouTube with the account from step 1 in a desktop browser.
2. Install a browser extension that exports cookies in **Netscape format** to `cookies.txt`, for example "Get cookies.txt LOCALLY". Check it is from a reputable source before installing.
3. While on youtube.com, use the extension to export cookies for the current site.
4. Open the exported file in a text editor and confirm it begins with `# Netscape HTTP Cookie File`. Do not paste it anywhere else.

Export again whenever YouTube starts asking for verification again. Cookies expire, and some sessions end when you sign out or change your password.

## 3. Place the file

- **On Render:** add it as a **Secret File** named `cookies.txt`. See `RENDER_DEPLOYMENT.md`, step 10.
- **On your own computer:** save it anywhere and set `COOKIES_PATH` to that full path, for example `COOKIES_PATH=/home/you/private/cookies.txt`. The default is `cookies.txt` in the project folder.

The startup log will then show `[BOOT] cookies.txt: N entries loaded`. The number of entries and expired entries are shown, never the values.

## 4. Deno (JavaScript runtime)

yt-dlp uses Deno to solve YouTube's challenges. The Docker image installs Deno during the build. For a local run, install Deno from https://deno.com and either put it on your PATH or set `DENO_PATH`. The startup log shows `[BOOT] Deno: OK` when it is found.

## 5. FFmpeg

FFmpeg merges video and audio into MP4 and converts audio to MP3. The Docker image installs it. For a local run, install FFmpeg (it must include `ffprobe`) and make sure it is on your PATH, or set `FFMPEG_PATH`.

## 6. PO tokens

Some YouTube clients now require a **PO token**, which is a short-lived proof generated by your device or a provider. The bot does not create, invent or hardcode a PO token.

If the bot reports "requires a PO token", you have two options:

1. Use a PO-token provider that you run or trust. yt-dlp's documentation describes how these work (search for "yt-dlp PO token guide").
2. Once you have a token from your provider, set it on the server:

   ```
   YT_EXTRACTOR_ARGS=youtube:po_token=web.gvs+YOUR_TOKEN_VALUE
   ```

   Keep this variable secret, like the cookies. Set it in the Render Environment tab, and mark it as a secret value.

## 7. Meaning of the messages

| Message | What it means | What to do |
|---|---|---|
| "YouTube asked for verification (not a bot)" | YouTube needs a logged-in session | Upload a cookies.txt (section 2–3) |
| "rejected the cookies.txt that was supplied" | The cookies were refused | Export fresh cookies and replace the file |
| "cookies.txt file was rejected (expired or invalid)" | The file is too old or malformed | Export a new file in Netscape format |
| "YouTube returned an incomplete page (The page needs to be reloaded)" | Temporary YouTube page problem, or yt-dlp is out of date. The bot retries once automatically | Wait a few minutes; if it persists, Clear build cache & deploy on Render and upload a fresh cookies.txt |
| "age-restricted" | The video needs an age-verified account | Use cookies from an age-verified account |
| "requires login" | Login is needed | Upload cookies |
| "PO token" | A client needs a PO token | Section 6 |
| "Deno … missing" | Deno is not available | Use the Docker image or set `DENO_PATH` |
| "FFmpeg failed or is missing" | FFmpeg is not available | Use the Docker image or install FFmpeg |
| "private", "unavailable", "members only" | The content cannot be accessed | Nothing to fix; the bot cannot download it |
| "blocked in the server's region" | Geographic restriction | Nothing to fix from the bot |
| "rate-limiting" | Too many requests | Wait a few minutes |
| "No downloadable format … at or below the selected quality" | The chosen height does not exist as a single stream | Choose a lower quality |

## 8. Limits to expect

- Telegram limits uploads from bots to 50 MB by default (`MAX_UPLOAD_MB`). Larger files are refused with a clear message.
- YouTube changes its behavior often. If downloads start failing across many videos, update the bot's dependencies (rebuild the image so `yt-dlp` is updated) and check the startup log.
